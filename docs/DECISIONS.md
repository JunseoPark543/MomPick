## 커뮤니티
- **게시판 범위**: "우리 동네" = 같은 **구**, 그리고 "전체글"(서울 전체 동네 게시판), "동기 모임"(아이 출생 연월이 같은 회원), "베스트". 글마다 동 이름을 표시. 회원이 늘면 동 단위로 좁힐 수 있다.
- **글을 쓸 때 게시판 선택**: 동네 게시판 / 동기 모임. 글쓴이의 동네와 아이 출생 연월은 **서버가 채운다** (다른 동네인 척 못 하게).
- **팩트 체크**: 회원은 출처를 단 "팩트 체크 댓글"로 기여(숲 맘 조건에 집계), 글의 "팩트 체크됨 / 확인 필요" 표시는 운영자가 단다.
- **사진**: 커뮤니티 글은 지금은 글만. 사진 업로드는 중고에서 먼저 만들었다.
- **베스트**: 좋아요 N개(설정값, 기본 10) 넘으면 자동 선정. 한 번 선정되면 유지(나무 맘 조건이라서). 운영자가 `best_at` 을 비워 취소 가능.
- **좋아요**: 내 글에는 못 누른다 (베스트 조작 방지).
- **신고**: 서로 다른 회원 N명(설정값, 기본 3)이 신고하면 자동 숨김. 운영자가 확인 후 해제. 채팅 신고는 자동 숨김 없이 운영자 확인.

## UI
- **레퍼런스는 화면 배치 패턴만 참고** (이름·로고·고유 디자인은 따라 하지 않음): 동네 = 네이버 카페형 목록, 중고 = 당근·번개장터형 목록, 마켓 = 쿠팡형 2열 상품 카드.
- **대표 색**: 로고 분홍 `#ED5D66`. 큰 글씨·큰 버튼.
- **중고 지역**: 회원은 기본 "내 구", 상단에서 다른 구·서울 전체를 고를 수 있다. 비회원은 서울 전체.

## 중고거래
- **거래 완료**는 판매자가 채팅방에서 구매자를 지정해 처리한다 (구매자 기록이 남아야 등급 계산 가능).
- **매물 사진**은 1280px 로 줄여 JPEG 로 다시 저장해 촬영 위치(GPS) 정보를 지운다 (실제로 지워지는지 확인은 BACKLOG).
- 안전결제 수수료 = 기본 수수료율 × (1 − 등급 할인) × (1 − 수수료 쿠폰). 모두 데모(실제 결제 없음).

## 등급·쿠폰
- 등급 규칙·쿠폰·배지·할인율·선구매 시간은 모두 DB(`grade_levels`, `coupon_templates`, `badges`, `app_settings`)에서 읽는다.
- **등급은 내려가지 않는다** (데모 단순화. 예: 구독 해지해도 숲 맘 유지) — 정식 출시 전 재검토.
- 등급이 오르면 그 등급 쿠폰을 자동 지급. Lv.1 환영 쿠폰은 플랫폼 부담 소액.

## 배포·구조
- **앱 고유 ID**: `com.mompick.app` (Android·iOS 공통, 바꿀 수 없음).
- **배포 순서**: 웹(EAS Hosting) + 안드로이드 테스트 APK 먼저. 아이폰은 Apple 개발자 계정 생기면 TestFlight.
- **저장소 구조** (2026-11-16): 모노레포 — 구매자 앱(Expo), 판매자 웹·관리자 웹(Next.js, Vercel), 공통 Supabase. npm 워크스페이스.
- **DB 변경**: Supabase CLI(`supabase/migrations/` + `npm run db:push`). 대시보드에 SQL 붙여넣기는 하지 않는다.
- **DB 타입**: `npm run db:types` 로 자동 생성 → `@mompick/shared`. 자동 타입이 모르는 규칙(서버가 채우는 칸, null 허용 인자)은 `packages/shared/src/index.ts` 에서 보정.
- **역할 구조** (2026-11-16): 계정은 하나(Supabase Auth), 역할은 표로 구분(`admin_users`, `seller_members`).
  - 입점: **판매자 신청 → 관리자 승인**. 승인 전에는 상품 등록 불가.
  - 특가: **판매자가 가격·기간 제안, "나무 맘 먼저"(선구매) 지정은 관리자만.** 노출 순서·평점도 관리자만.
  - 첫 관리자: **관리자 전용 계정**을 새로 만들어 지정 (일상 계정과 분리).
  - 관리자 작업은 모두 `admin_actions` 에 자동 기록. 채팅은 신고된 방만 관리자가 열람.
  - **작업 기록 요청 판별**(2026-11-16 수정): `log_admin_change()` 는 `SECURITY DEFINER` 라서 `current_user` 대신 `current_setting('role', true)` 로 API 요청 역할을 확인하고 `is_admin()` 으로 관리자 여부를 검증한다. 서버 내부 계산을 구분하는 guard 의 `is_api_request()` 는 현재 실행 역할을 계속 사용한다. 이 차이를 지우면 기록 누락 또는 서버 계산 차단이 생길 수 있다.
  - 판매자는 자기 상품이 든 주문의 배송지까지 볼 수 있다 (배송에 필요).
- **대표 페이지 디자인** (2026-11-16): 메인은 예비 회원용, 입점은 `/partners` 로 분리. 레퍼런스(당근 서비스 소개)처럼 **담백하게** — 카드·아이콘 타일·이모지·파스텔 쓰지 않기, 흰 바탕·큰 여백·큰 글씨, Pretendard. 사진은 **사용자가 직접 찍은 사진**(아이 얼굴 없이).
- **도메인** (2026-11-16): `mompik.com` (가비아, 기본 네임서버). 대표 `mompik.com`, 구매자 웹 `app.`, 판매자 `seller.`, 관리자 `admin.` — 웹 4개 모두 Vercel. 브랜드 표기는 MomPick 그대로.
